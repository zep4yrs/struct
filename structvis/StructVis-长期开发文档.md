# StructVis 长期开发文档

> 代号：StructVis  
> 定位：数据结构与数据库自学工具  
> 核心目标：提升自学者的学习效率  
> 附带价值：可作为教师课堂演示辅助  
> 状态：v0.1 规划中

## 一、项目定位

### 1.1 为什么做这个

自学数据结构和数据库时，最痛苦的不是语法记不住，而是**脑子里想象不出过程**。看书上的静态图示，看完好像懂了，一做题就错；跟着视频学，看起来很顺，自己写就卡壳。

StructVis 的存在就是为了解决这个问题——把抽象的算法过程变成**可交互、可步进、可自己动手试**的可视化练习，让自学者不靠老师也能把每个步骤搞明白。

### 1.2 不是什么

- 不是通用算法可视化网站（不是给所有人看的炫技 Demo）
- 不是在线 IDE（不是用来写项目的）
- 不是题库平台（不是刷选择题的）
- 不是课程平台（不卖课、不做视频）

### 1.3 是什么

- **教材对齐的自学辅助工具** — 跟着李春葆《数据结构教程》和杨宏霞《数据库技术及应用（MySQL）》的章节走
- **交互式步进可视化** — 不是看动画，是每一步都可以暂停、可以自己操作、可以试错
- **即时反馈的练习系统** — 做错了立刻告诉你为什么错，不是只给一个答案
- **本地进度追踪** — 学到哪了、掌握了多少、错了哪些，全在本地存着

### 1.4 目标用户

| 用户类型 | 核心诉求 | 占比预期 |
|---------|---------|---------|
| 自学者（你自己） | 学得懂、记得住、做得出题 | 100%（v0.1 唯一用户） |
| 同校学生 | 跟着教材学，做题不会了来练 | 未来可能的用户 |
| 授课老师 | 课堂演示用，代替黑板画图 | 附加价值 |

### 3.3 SQL Engine Adapter 设计

统一接口，两种实现，UI 层不感知差异：

```typescript
interface QueryResult {
  columns: string[];
  rows: Record<string, any>[];
  rowCount: number;
  executionTimeMs: number;
}

interface ExplainNode {
  id: string;
  operation: string;   // SCAN / SEARCH / SORT / TEMP B-TREE ...
  table?: string;
  index?: string;
  rows?: number;
  detail: string;      // 中文解释
  children: ExplainNode[];
}

interface SQLEngine {
  // 执行 SQL 查询
  execute(sql: string): Promise<QueryResult>;
  
  // 执行计划（统一格式输出，不管底层是什么数据库）
  explain(sql: string): Promise<ExplainNode>;
  
  // 当前方言
  getDialect(): 'mysql' | 'sqlite';
  
  // 加载示例数据库
  loadDatabase(name: string): Promise<void>;
  
  // 列出所有可用的示例数据库
  listDatabases(): string[];
}
```

### 3.4 方言适配层（sql.js 模式）

sql.js 模式下，执行 SQL 前经过一层轻量转换，让学生写 MySQL 方言也能跑：

| 转换项 | 处理方式 |
|--------|---------|
| `AUTO_INCREMENT` | 替换为 `AUTOINCREMENT`，并确保列是 `INTEGER PRIMARY KEY` |
| `ENGINE=InnoDB` / `DEFAULT CHARSET` | 直接 strip 掉 |
| `INT(n)` / `VARCHAR(n)` / `DATETIME` 等 | 保留（SQLite 动态类型，不报错） |
| `LIMIT offset, count` | 转换为 `LIMIT count OFFSET offset` |
| `IFNULL(col, val)` | 保持不变（SQLite 也支持） |
| `NOW()` / `CURDATE()` | 替换为 SQLite 等价函数 |
| 注释 `--` 和 `/* */` | 保持不变 |

适配层做**单向转换**（MySQL → SQLite），只处理教学中会碰到的常见语法，不追求完美兼容。遇到不支持的语法，明确提示"此语法需 MySQL 模式"。

### 3.5 算法引擎设计

每个算法是一个独立的步进状态机：

```typescript
interface AlgorithmStep {
  id: number;
  description: string;        // 一句话说明这一步在做什么
  data: any;                  // 这一步的状态数据（数组、树、图...）
  highlights: Highlight[];    // 高亮哪些元素（当前、已排序、pivot...）
  pseudocodeLine?: number;    // 对应伪代码第几行
}

interface AlgorithmEngine {
  name: string;
  pseudocode: string[];
  totalSteps: number;
  currentStep: number;
  
  init(input: any): void;     // 初始化，接受自定义输入
  next(): AlgorithmStep;      // 前进一步
  prev(): AlgorithmStep;      // 后退一步
  goTo(step: number): void;   // 跳到指定步
  reset(): void;              // 重置
}
```

每个算法自己生成完整的步骤序列，UI 层只管播放和渲染。这样算法逻辑和可视化完全解耦，换渲染方式不影响算法逻辑。

### 3.6 统一播放器架构

**核心设计模式：一套播放器 + N 个算法引擎（插件化）**

所有算法引擎实现同一个 `AlgorithmEngine` 接口，外面套一个通用的 `AlgoPlayer` 播放器容器。加新算法只需要写一个 Engine 类，不用改播放器一行代码。

```
┌─────────────────────────────────────────────────────────┐
│                    AlgoPlayer（通用，1个）               │
│  ┌───────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │  可视化渲染器   │  │  伪代码面板   │  │  控制面板     │  │
│  │  (按类型切换)   │  │              │  │              │  │
│  └───────────────┘  └──────────────┘  └──────────────┘  │
└───────────────────────┬─────────────────────────────────┘
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
     ┌─────────┐  ┌──────────┐  ┌──────────┐
     │快速排序  │  │二叉树遍历 │  │SQL分步执行│
     │ Engine  │  │ Engine   │  │ Engine   │
     └─────────┘  └──────────┘  └──────────┘
        ... 可插拔，N 个算法引擎 ...
```

**渲染器插件化**：可视化渲染器按数据结构类型独立，每个负责一种画法：

| 渲染器 | 适用算法 | 技术 |
|--------|---------|------|
| `ArrayRenderer` | 排序、数组操作 | Canvas 2D（柱状图） |
| `TreeRenderer` | 二叉树、BST、AVL | SVG + d3-shape（布局计算） |
| `LinkedListRenderer` | 单/双/循环链表 | Canvas 2D（节点+箭头） |
| `GraphRenderer` | 图的遍历、最短路径 | Canvas 2D（节点+边） |
| `SqlTableRenderer` | SQL 分步执行 | DOM 表格（高亮行/列变化） |

每个引擎声明自己的 `renderType`，播放器自动匹配对应的渲染器。

**练习模式统一框架**：交互式练习也是通用的，引擎自带练习题数据：

```typescript
type PracticeType = 'choose-next' | 'fill-array' | 'drag-pointer' | 'fill-code';

interface PracticeQuestion {
  type: PracticeType;
  stepIndex: number;           // 在第几步暂停出题
  prompt: string;              // 题目描述
  options?: string[];          // 选择题选项
  correctAnswer: any;
  hint: string;                // 提示（卡壳了看）
  explanation: string;         // 做完后的解析
}
```

播放器检测到当前 step 有对应练习题，自动暂停并弹出练习面板。

### 3.7 动画系统设计

**核心理念：两层结构 — 引擎关键帧 + 渲染补间**

直接跳帧会卡顿，解决方案是把"算法步进"和"视觉动画"分成两层：

```
算法引擎（关键帧）： step 0 → step 1 → step 2 → step 3 → ...
                         ↓ 补间插值（tween）
渲染层（补间帧）：   ●○○○●○○○●○○○●○○○●  （60fps 连续平滑）
```

- **引擎层**：只产出离散的关键帧（算法逻辑上的完整动作），完全不管动画
- **渲染层**：两个关键帧之间做平滑补间插值，60fps 连续渲染
- **播放控制器**：用浮点数 `playbackPos`（如 1.43）驱动，不是整数 step

**补间插值策略**（不同属性用不同方式）：

| 属性 | 插值方式 | 说明 |
|------|---------|------|
| 元素位置（x, y） | 线性插值 | 交换元素时柱子平滑滑动 |
| 柱子高度 | 线性插值 | 极少用（排序是交换位置不是改值） |
| 颜色 | HSV 空间插值 | 普通色 → 比较色 → 交换色 → 已排序色，平滑过渡 |
| 高亮状态 | 透明度淡入淡出 | 新高亮从 0→1，消失的从 1→0 |
| 伪代码行号 | 不插值，跳变 | 到了直接切，不用渐入 |

**步骤时长不一致**（节奏感，不是每步都一样快）：

| 步骤类型 | 时长建议 | 理由 |
|---------|---------|------|
| 比较元素 | 300ms | 快，一带而过 |
| 交换元素 | 600ms | 慢一点，看清怎么换的 |
| pivot 选定 | 400ms | 重要节点，稍微停 |
| 分区完成 | 800ms + 停顿 | 关键节点，给消化时间 |
| 递归进入/返回 | 500ms | 过渡感 |
| 全部完成 | 1000ms + 高亮 | 收尾仪式感 |

**GSAP Timeline 统一调度**：

不用自己写 `requestAnimationFrame`，用 GSAP timeline 管理所有动画：

```typescript
// 创建时间线，每两个关键帧之间加一段补间
const tl = gsap.timeline({ paused: true });

for (let i = 0; i < engine.steps.length - 1; i++) {
  const duration = getStepDuration(engine.steps[i + 1]);
  tl.to(renderState, {
    progress: i + 1,
    duration,
    ease: "power2.out",
    onUpdate: () => renderer.draw(renderState.progress),
  });
}

// 各种操作都是 timeline 的事：
tl.play()            // 播放
tl.pause()           // 暂停
tl.tweenTo(5)        // 平滑过渡到第 5 步然后停
tl.seek(3.5)         // 直接跳到 3.5 的位置（拖拽进度条用）
tl.timeScale(2)      // 2 倍速
```

**步进模式和自动播放完全兼容同一条时间线**：
- 自动播放 = `timeline.play()`
- 下一步 = `timeline.tweenTo(Math.ceil(currentPos))`
- 上一步 = `timeline.tweenTo(Math.floor(currentPos))`
- 跳到第 N 步 = `timeline.tweenTo(N)`
- 拖拽进度条 = `timeline.seek(value)`

不管怎么操作，动画永远是丝滑的，不会有跳帧或卡顿。

### 3.8 同步机制

**核心原则：单向数据流，算法引擎是唯一真相源（Single Source of Truth）**

```
                    ┌──────────────┐
                    │  算法引擎     │  ← 唯一真相源
                    │  Engine      │
                    │  steps[]     │
                    │  currentPos  │
                    └──────┬───────┘
                           │ 只读数据流（下行）
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ Canvas   │ │ 伪代码面板 │ │ 进度文字  │
        │ 可视化    │ │          │ │          │
        └──────────┘ └──────────┘ └──────────┘
              ▲            ▲            ▲
              └────────────┼────────────┘
                           │ 唯一上行：状态修改
                    ┌──────┴───────┐
                    │  控制面板     │
                    │  （唯一入口）  │
                    └──────────────┘
```

**规则**：
1. 只有控制面板能修改引擎状态（调用 `next()` / `prev()` / `goTo()` / `play()` / `pause()`）
2. 所有其他模块都是"视图"，只读引擎状态，不自己存状态
3. 引擎状态变了，所有视图自动重绘（Svelte 响应式天然支持）

**Svelte 5 中的实现**：

```svelte
<script lang="ts">
  // 引擎是响应式状态
  let engine = $state(new QuickSortEngine());
  
  // 派生当前进度（自动响应）
  let currentStep = $derived(engine.steps[Math.floor(engine.playbackPos)]);
  let tweenProgress = $derived(engine.playbackPos % 1);
</script>

<!-- 所有视图只读取，不修改 -->
<ArrayRenderer step={currentStep} tweenProgress={tweenProgress} />
<PseudocodePanel lines={engine.pseudocode} activeLine={currentStep.pseudocodeLine} />
<ControlBar 
  onNext={() => engine.next()} 
  onPrev={() => engine.prev()}
  onPlay={() => engine.play()}
/>
```

为什么不会乱？因为**只有一个地方能改状态**，其他所有地方都是纯渲染。数据流永远是单向的：控制面板 → 引擎 → 所有视图。

## 六、设计系统

### 6.1 视觉风格

定位：**编辑技术极简主义（Editorial Technical Minimalism）**

- 排版为核心，色彩为信号
- 纸白底（#FAF9F6）+ 墨黑字（#1A1A1A）
- 衬线体做标题（Fraunces），无衬线体正文（DM Sans），等宽体代码（JetBrains Mono）
- 0.5px 细线边框，3~10px 小圆角
- 琥珀色（#D97706）做当前步进高亮
- 全局极淡纸纹，增加质感

完整设计规范见 `N08-UI-Design.md`，视觉参考见 `ui-design-reference.html`。

### 6.2 交互原则

1. **键盘优先** — 所有操作都能键盘完成（步进用左右箭头，空格播放/暂停）
2. **即时反馈** — 操作后 100ms 内必须有视觉反馈
3. **状态永远可见** — 当前第几步、对了错了、进度多少，一眼就能看到
4. **不靠颜色 alone** — 状态除了颜色还有图标或文字标注
5. **动效服务理解** — 动画可以暂停、减速、单步，不搞花活

## 八、部署方案

### 8.1 v0.1 - v0.2（纯静态）

- 构建：`npm run build`（adapter-static）
- 产物：`build/` 目录
- 部署：GitHub Pages（免费、自带 HTTPS）
- 域名：可选自定义域名或用 `username.github.io/structvis`
- 自动部署：GitHub Actions，push 到 main 自动构建发布

### 8.2 v0.3+（可选后端）

如果加了 MySQL 后端模式：

- 前端：不变，继续 GitHub Pages
- 后端：Node.js + Express，部署到 Vercel / Cloudflare Workers（Serverless）
- 数据库：TiDB Serverless（免费额度够用，自动扩缩）
- 通信：前端配置后端地址后，走 HTTPS API 调用

架构上前端完全独立，后端是可选增强，不配置就是纯静态版本。

| 风险 | 影响 | 概率 | 应对 |
